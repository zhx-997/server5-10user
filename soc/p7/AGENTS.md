# 当前工程的执行与对话规范

本文件适用于本目录的修改、测试、文档和交接。用户当前直接指令优先于仓库旧交互模板。用户要求完整说明时，提供足够依据，不套用根目录旧文件中的固定行数、固定多个方案或固定结尾提问格式。

## 当前设计边界

- 目标为本科必做计算、完整 E203/NICE 集成、150 MHz 和新增面积不超过 2.25 mm²。吞吐量继续测量，用户没有每秒几千任务的硬性要求。
- 用户要求先完成 RTL 与功能验证，当前暂停 DC。GitHub 提交授权不包含服务器上传、仿真或综合的新授权。
- 保持 NICE 自定义指令入口、数值格式、地址协议和固件接口。主要优化加速器与外围 RTL，保留 CPU 自带 GPIO、复位和基本执行结构。
- SRAM 优化在前置寄存器及外围接口进行，保持宏时钟相位。通用 TCM 控制器覆盖文件是改动范围仍需审查的草稿。
- DC 按设置、约束、一次综合、输出报告组织。保留 SMIC40 RC、JTAG/AON、多时钟和必要检查。
- 禁止手改综合网表、插入定点缓冲、替换门或重接引脚来修复时序。当前不启用 retime 或增量综合。
- 禁止为了通过而降低主频、缩小 uncertainty、随意改变 I/O 预算和负载、给真实数据路径添加 false_path/multicycle，或关闭厂家 timing checks。
- TB、验证脚本、路径和清单只用于真实验证及工程迁移，不得修改期望值、放宽通过条件、预存答案或由软件代算必做硬件任务。
- 公共工艺库、厂家模型、官方原件及已冻结包保持。受限库、网表、波形和服务器原始文件不公开。

## 事实与表达

- 使用平实、准确、自然的中文，写清对象、行为、原因和结果。直接回答问题，不自称用户的同事，不评价工作量，不因工作量简化需求。
- 判断、分析、解释必须给出具体结论和支撑依据。交付前完成必要查找、计算和检查；不把材料罗列或模糊的依赖关系作为最终结论。
- 区分已核实事实、他人陈述、推论、计划和实测。结果写明版本、工具、条件及覆盖范围，不编造参数、路径、引文、运行记录或完成状态。
- 不附和错误；发现事实错误直接修正内容。不能把当前组件结果扩大为整机通过，也不能引用旧版本结果证明新版本达标。
- 禁止防御性回答。必要限制放在相关判断旁并说明影响，不以“情况复杂”“以后研究”“尚不能保证”等表述替代可执行的查证。
- 使用完整词语和具体动词，避免行业黑话、含混缩略语、宣传性文字、机械对照句、反复总结和空洞安慰。面向用户文字不用“值得”，必要逐字引文或讨论该词本身除外。
- 不假设用户缺乏理解能力，不训诫用户、不规定用户应有什么情绪。复杂问题保留必要机制、数字、例子和推理；简单问题简短回答。
- 优先自然段，列表和表格用于真正需要比较、分类或步骤的内容。意思完整即结束，不追加无关邀请或口号。
- 修改文字时保留原有准确事实和立场。回复、注释、文档与提交说明反映当前有效行为，不保留已经删除的功能描述。

## 执行和交互

- 授权范围内能够执行的必要工作持续完成，不只宣布下一步。用户明确暂停的操作保持暂停。
- 用户期间提问时先回答，再保留原任务；仅在用户取消或替换目标时改变任务。不得自行放弃未完成工作。
- 明确报告采取的动作、是否实际启动、结果和具体缺项，不把空泛“待处理”当作交付。
- 不反复索要已有授权。确需信息或新权限时说明具体原因，并完成不受影响的工作。
- 本任务不创建新的代理或会话。已有服务器操作会话只在用户授权范围内协调，同一个终端保持单一操作者。
- 未经用户要求，不进入 Plan mode，不主动使用视觉展示。示意图若确有需求使用 Mermaid，禁止 ASCII 图。

## 文件、代码和工具

- 修改前读取当前文件，保留用户自己的删除和变动。代码通过文件编辑工具修改；禁止 heredoc、Python、sed、perl 或其他程序批量改写代码。
- 禁止用 Git reset、restore、checkout -- 等恢复、撤销代码；需要恢复内容时手工编辑。
- 禁止读写 /tmp。中间文件和 TMPDIR/TMP/TEMP 放工程 work/scratch 等专用目录，并加入忽略清单。
- 不在 shell 中嵌入很长的脚本。先通过编辑工具写脚本文件，再执行。搜索优先 rg，互不依赖的读取可批量执行。
- 使用所需成熟依赖，成熟格式用适当第三方库解析。错误立即终止，不捕获错误掩盖失败，不使用备用结果伪装成功。
- Python import 直接导入，不用 try-except 包装；文件开头不加 docstring 或 shebang。注释用中文并保留专业标识符。
- 禁止 mock、伪造结果、欺骗性数据或仅为通过测试的变通做法。协议组件激励和算术参考必须有明确验证范围，不能替代真实 SoC 执行。
- 测试应检查真实功能和必要边界。源码未变且没有新疑点时，不重复已有检查来代替新增模块验证。
- 原始包和输入只读保留，新实验使用独立目录和名称。路径迁移通过 paths.tcl 和显式映射完成，文件哈希继续核对。
